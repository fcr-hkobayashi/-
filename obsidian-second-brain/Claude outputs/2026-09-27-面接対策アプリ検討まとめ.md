## 1. ゆう版計画書（2026-09-24）の要旨

- 一行：**動画で学んだ型を、今日受ける1社の募集要項に落として、面談を突破させるまで回すアプリ**
- 前提：面接対策SaaSは年5万円以下が相場。30〜90万円で売れているのは「人の伴走」と「結果へのコミット」
- 商品は4点セット：動画（型を教える）／アプリ（型を1社に適用・可視化）／人（止まった時に動かす）／保証（突破率が根拠）
- 製品の芯：話し方の採点ではなく **一貫性の検査**（根っこ一行→要件マッピング→20問→深掘り→一貫性検査）
- 2モード：採用面接モード／案件面談モード（案件面談は既存製品がなく先発を取れる）
- 6軸ルーブリック：必須＝一貫性・深さ・具体、補助＝固有性・安全性・順番
- 段階：v1（募集要項分解・企業リサーチ・20問）→ v2（記録・行動量・突破率・動画ひも付け）→ v3（根っこ一行・深掘り・6軸FB）→ v4（経歴・マッピング・逆質問・確認リスト・一貫性レポート）
- 作らない：話し方分析／求人サイトの自動スクレイピング／自由チャット／点数表示

## 2. 第三者レビュー

### 2-1. 点数

- 初回評価：**65/100**（社内の構想メモとしては80点、決裁用の計画書としては65点。考え方85点・書類の詰め60点）
- 議事録を踏まえた時点：このまま竹人さんに出すなら60点（対象者と完結方針が議事録とずれていたため）
- 前提修正後（マキカエシ＝高単価副業、ゴール＝契約締結）：**70点**。下記の修正を入れれば **85点前後**

| 評価項目 | 点数 | 一言 |
|---|---|---|
| 課題設定・差別化 | 18/20 | 「一貫性の検査」「案件面談の先発」は鋭い |
| 構成・読みやすさ・決裁の促し方 | 14/15 | 結論が先、13章の論点整理がきれい |
| 根拠の強さ | 8/20 | ほぼゆう1人の体験（n=1） |
| 内部の整合性 | 11/20 | 章どうしの矛盾が複数 |
| 実行できるか | 9/15 | v1の1週間は可能、v2以降の前提が抜けている |
| 事業性（収益・コスト） | 5/10 | 50万円・結果保証を支える試算がない |

### 2-2. 良い点

- 「アプリ単体では50〜100万にならない」と先に認め、アプリを「伴走を少人数で回す道具」に絞っている
- 話し方ではなく一貫性で勝負する差別化が、実際に落ちる理由から逆算されている
- 作らないものを理由つきで決めている
- F8（確認必須リスト）を「判定」ではなく「確認」にしている＝外した時の害を避けている

### 2-3. 矛盾点（重要な順）と現在の扱い

| # | 矛盾 | 現在の扱い |
|---|---|---|
| 1 | ログインを作らないのに、記録・突破率（F12〜14）を出そうとしている | 管理アプリ・データ保存の方針が出て **解消方向** |
| 2 | 差別化の核（一貫性レポートF11）がv4、根っこ一行・FBがv3 | 順番を入れ替える（4章） |
| 3 | 案件面談モードを先に出したいのに、そのデータがゼロ | 2人の副業面談データが対象領域と一致し **解消** |
| 4 | 「骨格共通・開発コストほぼ増えない」は成り立たない（落ちる理由が違う） | 採用面接モードは不要。**案件タイプ別**に作り直す |
| 5 | 「自動取得しない」とF2（企業情報の自動収集）が同居 | URL入力＋本文貼り付けの二段構え |
| 6 | 「保存しない」とF3・F12（使い回し・質問DB）が同居 | 「全部保存」方針なら規約・同意画面を最初から入れる |
| 7 | 「アプリ単体で課金しない」と「繰り返し使われるのが強み」がかみ合わない | 価格とあわせて後日検討 |
| 8 | 役割分担に「データ提供者としての隼人」が抜けている | 役割を3つに（6章） |

細かい点：「製品の心臓」が3か所ある／F8が「新機能不要」なのに別番号／定例が「週数回」と「週2回」／「無料で回す」と書いているがAPI料金は発生する。

### 2-4. 根拠の弱さ

- 6軸・「良い内容でも人は払わない」・「突破要因は根っこ一行」は、どれも1人の体験から導かれている → **仮説として扱い、検証方法と期限を書く**
- 「既存アプリは100%採用面接向け」は調べた範囲が書かれていない
- 面接で聞いた他社の内部情報は、社外向け資料には使わない
- 「突破率◯%」を広告に使う場合は、母数と条件を必ず添える（少ない母数だと景品表示法上のリスク）

## 3. 議事録（第1回相談 2026-09-25）で変わった前提

- 竹人さん（クライアント）から「合格できるようなアプリを作ってほしい」という依頼。意図の深掘りが必要
- 金額感50万〜100万円は **講座全体** の想定で、正確な金額はまだ聞いていない
- 目標：合格・採用までを **アプリ内で完結**
- 機能案：応募履歴の蓄積／募集要項URLの読み込み／Googleカレンダー連携／ゲンさんのコーチングで決めた言葉をオープニングに表示／TAKETOさんの面接対策MDを組み込む／運営が入力を見られる管理アプリ（隼人のGoogle Cloud＋LINE通知の仕組みを流用）
- 検討事項：LLM機能はコストが発生する／受講者のClaude Code・Codex課金を前提にする案／MDは使うAIで出力が変わる
- 進め方：計画書を竹人さんに出して方向確認 → 骨組みを作って修正を重ねる
- 指摘：N1がゆう1人分だけ → 隼人のナレッジも必要／フィードバックの質が差別化の鍵

### 議事録を踏まえた判断

- **「アプリで完結」と「運営が見てFB」が同居** → マキカエシ自体が伴走型なので「面接対策の作業はアプリで完結、動機づけと節目の判断は人」と読み替える
- **受講者のAIツール課金前提は外す** → サーバー側でAPIを1本使い、品質をそろえる（「プロンプトをコピーして自分のAIで使う」は予備）
- **Googleカレンダー本格連携は重い**（認証と審査が必要）→ 最初は「カレンダーに追加」リンクで代用
- **LINE通知** は LINE Notify が2025年3月に終了しているため Messaging API 前提

## 4. 前提修正後に新しく重要になったこと

1. **最大の課題は面接より手前の「実績がないこと」**
   - 隼人とゆうは営業・店舗運営の実績を持って応募した。受講者はAIを学んだばかり
   - → 経歴・AI実績の棚卸し（F3/F4）をv4から **v1へ前倒し**
   - → 「AIで作った成果物を見せる」準備（ツール実演動画・ポートフォリオ）を追加
2. **「合格」だけを追うと収入増とぶつかる**
   - 成果報酬のみ・研修無償・会費ありなど、時給換算で割に合わない案件にも合格させてしまう（ウルサポの件）
   - → 確認必須リスト（F8：時給換算・稼働・固定費）を **v1へ前倒し**
   - → 指標は「契約数」と「条件を満たした契約数」
3. **ルーブリックの7軸目＝「副業としての信頼」**
   - 「片手間に見られないか」（稼働・継続・連絡体制）。隼人が面談で最も警戒した点
   - → 必須3軸（一貫性・深さ・具体）＋この軸の **4軸** で始める
4. **採用面接モード／案件面談モードの2分割はやめ、案件タイプ別にする**
   - 反響営業／IS・新規開拓／Webマーケ／CS・AI導入支援

## 5. 修正版の設計（計画書 土台 v0.1 の内容）

### ユーザーの流れ

1. 起動：コーチングで決めた「自分の言葉」が最初に表示される
2. 準備：経歴とAI実績を一度登録し、以後は使い回す
3. 応募：募集要項を入れると、案件タイプ判定・想定質問・確認リストが出る
4. 面談：日程を登録し、前日に深掘り練習をする
5. 記録：聞かれたこと・詰まったこと・結果を残す

### 作る順番

| 版 | 中身 |
|---|---|
| v0（今日から） | 記録・行動量はGoogleフォーム＋スプレッドシートで先に始める（コード不要） |
| v1 | オープニングの言葉／経歴・AI実績の棚卸し／募集要項（URL or 本文）→ 案件タイプ判定・表と裏の要件 → 想定質問（頻出10＋案件特有10、各問に「見られている点」「地雷」）／確認必須リスト＋時給換算／応募履歴＋「Googleカレンダーに追加」 |
| v2 | 根っこ一行／深掘り練習＋4軸フィードバック／管理画面＋LINE通知／突破率（面談通過率・契約率、母数と条件を表示） |
| v3 | 実演動画・ポートフォリオの台本支援／一貫性レポート／実際に聞かれた質問DB／動画各回とのひも付け |

### 作らないもの

| 作らないもの | 理由 |
|---|---|
| 話し方・表情・声の分析 | 落ちる理由ではない。処理コストも最も高い |
| 求人サイトの自動収集 | 利用規約に触れる恐れ。募集要項はユーザーが入れる |
| 自由チャット | コストが読めず、回答の質がぶれ、記録が資産にならない |
| 点数表示 | 「78点」では直せない。崩れた箇所の位置だけ出す |
| 「受けるべきか」の判定 | 外したときの害が大きい。確認必須リストで代替 |
| カレンダー本格連携（v1時点） | 認証と審査が重い。追加リンクで代用 |

### フィードバック4軸

| 軸 | 何を見るか | 出所 |
|---|---|---|
| 一貫性 | 根っこ一行から導けるか | ゆうの面接記録 |
| 深さ | 「なぜ？」を3回重ねても根拠が残るか | ゆうの面接記録 |
| 具体 | 実体験・数字に紐づくか | ゆうの面接記録 |
| 副業としての信頼 | 稼働・継続・連絡体制を具体的に語れるか | 隼人の副業面談記録 |

- 水準は「明日の面談までに直せる指摘」。各軸にOK例・NG例を最低2つずつ用意する

### 技術構成とデータ

- Webアプリ1つ＋サーバー側のAI API 1本＋データ保存＋管理画面
- APIキーは画面側に置かない（サーバーの環境変数）。利用上限を設定する
- プロンプトはコードと別ファイル（ゆうが直接編集できる）
- AIの出力は **JSONで固定**（記録・質問DBにそのまま貯める）
- ベースのプロンプトはTAKETOさんの面接対策MDを副業面談向けに作り直す
- 利用規約・プライバシーポリシー・同意画面は骨組みの段階から入れる
- 実装の目安（Claude Code初心者前提）：Next.js＋Vercel、画面1枚・API呼び出し1本から

## 7. 「今までの自分」の強みの使いどころ

- 手持ちの面接対策プロンプト（STEP1〜6・/模擬）・対策シート・面談ログ・日報運用が、v1〜v2の中身とほぼ重なる → ゼロから作らず流用する
- 店舗拡大（1→3店舗）と同じ順番で進める：自分で検証 → 勝ちパターンを数字にする → テスターに広げる
- 採算管理の経験で、損益（受講単価・伴走工数・返金率・獲得コスト）を組み立てられる
- 高単価講座の「説明会→個別面談→成約」の流れを見ているので、突破率の使い方を売る側の目線で設計できる
- 変えた方がいい点：対策シートづくりに力を使いすぎず、**面談後5分で結果を記録する**習慣に振り替える（言語化の練習にもなる）
