# 面接対策アプリ

## 🎯 ゴール（何が達成できたら完了か）
- マキカエシ受講者が、副業案件の **契約締結** まで到達できるアプリを作る（竹人さんからの依頼「合格できるアプリ」）
- 「合格」の定義＝**契約の締結**（確定）
- 成果指標：契約数と、そのうち条件（単価の時給換算・稼働・固定費）を満たした契約の数

## 🧭 第1回相談（2026-09-25）で出たこと
- ターゲット仮置き：35歳以上のマキカエシ受講者（ペルソナは上司とすり合わせて確定）
- ゴール：副業の面接・選考に合格し、採用までをアプリ内で完結
- 機能案：応募履歴の蓄積／募集要項URLの読み込み／Googleカレンダー連携／ゲンさんのコーチング（ゴール・言葉）をオープニングに表示／TAKETOさんの面接対策MDを組み込む／運営側の管理アプリ（Google Cloud＋LINE通知を流用）
- 進め方：計画書を竹人さんに出して方向性を確認 → 骨組みを作って修正を重ねる
- 指摘：N1がゆう1人分だけ → 自分のナレッジも必要／フィードバックの質が差別化の鍵

## 📝 計画書（ゆう版）へのレビュー要点
### 点数
- 最初の評価：65/100（考え方85点・書類としての詰め60点）
- 前提修正後（マキカエシ＝マーケ・AIコンサル高単価案件、ゴール＝契約締結）：70点。修正を入れれば85点前後

| 評価項目 | 点数 |
|---|---|
| 課題設定・差別化 | 18/20 |
| 構成・決裁の促し方 | 14/15 |
| 根拠の強さ | 8/20 |
| 内部の整合性 | 11/20 |
| 実行できるか | 9/15 |
| 事業性（収益・コスト） | 5/10 |

### 良い点
- 「アプリ単体では50〜100万にならない」と先に認め、アプリを伴走の補助に位置づけている
- 「話し方の採点ではなく一貫性の検査」という差別化
- 作らないものを理由つきで決めている／F8を「判定」ではなく「確認リスト」にしている

### 主な矛盾・弱点
1. ログインなしで記録・突破率を出そうとしている（9章 ⇔ v2）→ 管理アプリ・データ保存の方針で解消方向
2. 差別化の核（一貫性レポートF11）が最後のv4
3. 案件面談モードを先に出したいのに、そのデータがない → 前提修正で2人のデータが対象領域と一致し解消
4. 「骨格共通・開発コスト増えない」は成り立たない（落ちる理由が違う）→ 採用面接モードは不要、案件タイプ別に作り直す
5. 「自動取得しない」とF2の企業情報自動収集が同居
6. 「保存しない」とF3・F12（使い回し・質問DB）が同居 → 「全部保存」方針なら同意・規約が必要
7. アプリ単体で課金しない ⇔ 繰り返し使われるのが強み
8. 役割分担に「データ提供者としての隼人」が抜けている
- 根拠がほぼn=1、損益・結果保証の試算がない、「既存アプリ100%採用面接向け」は未検証

### 前提修正で新たに重要になったこと
- 最大の課題は面接より手前の **「実績がないこと」** → 経歴・AI実績の棚卸しをv1に、実演動画・ポートフォリオ支援をv3に
- 合格だけ追うと割に合わない案件でも合格させてしまう → **確認必須リスト（時給換算・稼働・固定費）をv1に**
- ルーブリック7軸目＝ **「副業としての信頼」**（稼働・継続・連絡体制。「片手間に見られないか」）
- 受講者のAIに依存せず、サーバー側でAPIを1本使う（品質をそろえる）

## 🛠 修正版の作る順番（叩き台）
| 版 | 中身 |
|---|---|
| v1 | オープニングの言葉／経歴・AI実績の棚卸し／募集要項 → 案件タイプ判定（反響営業・IS新規・Webマーケ・CS/AI導入支援）→ 想定質問（見られている点・地雷）／確認必須リスト／応募履歴＋「Googleカレンダーに追加」リンク |
| v2 | 根っこ一行／深掘り練習＋4軸FB（一貫性・深さ・具体・副業としての信頼）／管理画面（LINE通知はMessaging API）／突破率の集計 |
| v3 | 実演動画・ポートフォリオ台本／一貫性レポート／実際に聞かれた質問DB／動画各回とのひも付け |

- 作らないもの：話し方分析／求人サイトの自動収集／自由チャット／点数表示／「受けるべきか」判定／v1でのカレンダー本格連携
- 技術：プロンプトはコードと別ファイル（ゆうが編集できる）、AI出力はJSON固定、規約・同意画面は最初から

## 👥 役割分担（案）

- ゲンさん：コーチングシートの形式共有
