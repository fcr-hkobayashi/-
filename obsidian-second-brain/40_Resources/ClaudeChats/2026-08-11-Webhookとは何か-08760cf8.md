# Webhookとは何か

> claude.ai の会話ログ（エクスポート由来）。作成 2026-08-11 / 更新 2026-08-20

### **あなた**

web hookとは

### **Claude**

**Webhook(ウェブフック)**とは、あるアプリで何か出来事(イベント)が起きたときに、別のアプリへ自動的に通知を送る仕組みのことです。

**簡単なイメージ**
- 「イベントが起きたら、指定したURLに自動でデータを送る」という一方通行の通知
- 相手側は常に監視(ポーリング)しなくても、イベントが起きた瞬間にリアルタイムで知ることができる

**具体例**
- GitHubに新しいコミットがpushされた → 登録しておいたSlackのURLに通知が飛んで、Slackチャンネルに自動投稿される
- ECサイトで支払いが完了した → 決済サービスが「支払い完了」というデータを、店舗側のサーバーURLに自動送信する

**通常のAPIとの違い**
| | 通常のAPI | Webhook |
|---|---|---|
| 動き方 | こちらから「情報ある?」と聞きに行く(プル型) | 向こうから「起きたよ」と教えてくれる(プッシュ型) |
| タイミング | 自分で好きな時に呼ぶ | イベント発生時に自動で呼ばれる |

要は「イベント駆動型の自動通知URL」と考えると分かりやすいです。何か具体的な場面(例えば特定のサービスの設定など)で疑問があれば教えてください。

### **あなた**

Slackとは

### **Claude**

**Slack(スラック)**は、企業やチームで使われるビジネス向けチャットツール(コミュニケーションアプリ)です。

**主な特徴**
- **チャンネル**:話題やプロジェクトごとに会話の場所を分けられる(例:#general、#開発チーム、#雑談)
- **ダイレクトメッセージ(DM)**:個人間やグループでの1対1・少人数のやり取り
- **スレッド機能**:特定の投稿に対して返信をまとめられるので、話が脱線しにくい
- **ファイル共有**:画像や資料をチャット上でやり取りできる
- **外部ツール連携**:GitHub、Googleカレンダー、Trelloなど様々なサービスと連携可能

**さっきのWebhookとの関係**
まさに先ほど説明したWebhookの代表的な使い道の一つがSlackです。例えば、
- GitHubにコードがpushされたら自動でSlackチャンネルに通知
- ECサイトで注文が入ったら自動でSlack通知
- サーバーに障害が起きたらSlackにアラートを飛ばす

といったように、「外部サービスの出来事をSlackに自動で流し込む」ためにWebhookがよく使われます。

メールと違って、リアルタイム性が高く、会話がチャンネルごとに整理されるので、リモートワークをするチームなどで広く使われています。

### **あなた**

Apps scriptとは

### **Claude**

**Google Apps Script(グーグル アップス スクリプト、略称GAS)**は、Googleが提供する無料のプログラミング環境で、Google スプレッドシート・Gmail・Googleカレンダー・Googleドライブなどのサービスを自動化・拡張できるツールです。

**主な特徴**
- JavaScriptベースの言語で書く(プログラミング初心者でも比較的とっつきやすい)
- ブラウザ上でそのままコードを書いて実行できる(環境構築が不要)
- Googleの各サービスに直接アクセスできる専用の命令(API)が用意されている

**よくある使い方**
- スプレッドシートに新しい行が追加されたら自動でメールを送る
- 毎朝決まった時刻にスプレッドシートのデータを集計してSlackに通知(← ここでもWebhookの仕組みが使われる)
- フォームの回答が来たら自動で返信メールを送る
- 定型的な事務作業(転記・集計・通知)を自動化する

**位置づけ**
| ツール | できること |
|---|---|
| Excelマクロ(VBA) | Excel内の作業を自動化 |
| Google Apps Script | Googleサービス全体(スプレッドシート・Gmail・カレンダー等)を横断して自動化 |

いわば「Googleサービス版のマクロ+外部連携ツール」というイメージです。日常業務の面倒な繰り返し作業を自動化したいときによく使われます。

何か具体的にやりたいこと(例:スプレッドシートの自動集計など)があれば、それに合わせて説明できます。

### **あなた**

JavaScript

### **Claude**

JavaScriptとは

**JavaScript(ジャバスクリプト)**は、主にWebサイトやWebアプリに「動き」や「機能」を与えるためのプログラミング言語です。

**役割のイメージ**
| 言語 | 役割 |
|---|---|
| HTML | ページの骨組み(文章・画像などの中身) |
| CSS | 見た目・デザイン(色・レイアウト) |
| JavaScript | 動き・機能(クリックしたら反応する、計算する、データを送るなど) |

**できることの例**
- ボタンを押したら画面の表示が切り替わる
- 入力フォームの内容をチェックする(空欄のままだと送信できない、など)
- サーバーとデータをやり取りする(さっきのWebhookで送られてきたデータを受け取って処理する、なども)
- ゲームやアニメーションを作る

**今までの話とのつながり**
- **Google Apps Script**は、実はこの「JavaScriptがベース」になっている言語です。つまりApps Scriptを書けるようになると、JavaScriptの基礎も身についていることになります。
- Webページも、Slackの通知を受け取るサーバー側の処理も、JavaScript(またはその派生)で書かれていることがよくあります。

**特徴**
- ブラウザさえあれば動く(特別なソフトのインストール不要)
- 現在、世界で最も広く使われているプログラミング言語の一つ
- 「フロントエンド」(画面側)にも「バックエンド」(サーバー側、Node.jsという仕組みを使う)にも使える

もしご自身で何か自動化やアプリ作りに挑戦したい場面があれば、それに合わせて具体的な書き方も説明できます。

### **あなた**

トンマナってなに

### **Claude**

**トンマナ**は「トーン&マナー(Tone & Manner)」の略で、デザインや文章・ブランドなどにおける**一貫した雰囲気・世界観のルール**のことです。

**具体的には何を指す?**
- 色使い(カラーパレット)
- フォント・書体
- 写真やイラストのテイスト
- 文章の口調(丁寧語か、カジュアルか、絵文字を使うかなど)
- レイアウトの雰囲気(かっちりしているか、柔らかいか)

**なぜ重要?**
複数のページ・資料・投稿を作るときに、これらがバラバラだと「同じブランド・サービスなのに雰囲気が違う」という違和感が生まれます。トンマナを決めておくことで、**誰が作っても統一感のある見た目・印象**になります。

**使われる場面の例**
- 「このLPは弊社サイトのトンマナに合わせて作ってください」→ 既存サイトと同じ色・フォント・雰囲気で
- 「もう少しトンマナを柔らかくしたい」→ 硬い印象から親しみやすい印象へ変更
- 「このプレゼン資料、トンマナがバラバラだから統一して」→ フォントや配色を揃えて

要は「**見た目・言葉づかいの統一されたスタイルガイド**」というイメージです。デザインやマーケティング、Web制作の現場でよく使われる言葉です。
