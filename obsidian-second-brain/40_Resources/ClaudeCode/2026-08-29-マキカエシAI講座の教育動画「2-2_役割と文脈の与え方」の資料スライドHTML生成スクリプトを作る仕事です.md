# マキカエシAI講座の教育動画「2-2 役割と文脈の与え方」の資料スライドHTML生成スクリプトを作る仕事です

> Claude Code セッション記録（2026-08-29 〜 2026-08-29）。ツール実行ログは除外。

### **あなた**

マキカエシAI講座の教育動画「2-2 役割と文脈の与え方」の資料スライドHTML生成スクリプトを作る仕事です。既存の2-1案件と全く同じ枠組み・CSSクラスで、2-2の37枚を作ります。

## 参照（必ず読む）
- 枠組みテンプレート: `/Users/hayato.kobayashi/Downloads/2-1案件/screens/mkscreens.py` と `mkscreens2.py`（head/_tfont/page/BB/card/kicker/krow/sixmini/grid6/li/el/row の各ヘルパー定義。これを流用する）
- CSS: `/Users/hayato.kobayashi/Downloads/2-1案件/screens/style.css`（使えるクラスの一覧）
- 2-2のスライド設計（内容の正解）: `/Users/hayato.kobayashi/Downloads/2-2案件/資料.pptx` — python-pptx で全37スライドのテキストを抽出して内容を確認すること（`~/.venvs/edit/bin/python` を使う）

## 作るもの
`/Users/hayato.kobayashi/Downloads/2-2案件/screens/mkscreens.py` を新規作成し、実行すると `slide_01.html`〜`slide_37.html`（同ディレクトリ、1280x720）を出力するようにする。`style.css` は既に同ディレクトリにコピー済み。

## 枠組みの必須事項
- 各ヘルパー（head/_tfont/page/BB/card/kicker/krow/sixmini/grid6/li/el/row）は2-1のmkscreens.py/mkscreens2.pyから**そのままコピー**して使う。特に `page(n, inner)` は `<div class="slide">{inner}</div>{BB}` を書く（BBはgetBoundingClientRect抽出用scriptで、2-1のmkscreens2.pyにある定義をそのままコピー）。
- `NAV = ["はじめに", "文脈が土台", "役割は物差し", "入れるもの", "やってみる"]`、`TOTAL = 11`。
- `head(eyebrow, title, chapter, page, navon)` の第4引数pageは章番号(1..11)、navonはNAVのどれをオンにするか。

## 章→スライド対応（pptxの進行的リビール。合計37枚）
pptxは各章が段階的に要素を足していく作り。各章のサブスライド数とnav:
- 章1 slide01-03（3枚）eyebrow「はじめに」nav「はじめに」page1
- 章2 slide04-06（3枚）eyebrow「文脈が土台」nav「文脈が土台」page2
- 章3 slide07-09（3枚）eyebrow「役割は物差し」nav「役割は物差し」page3
- 章4 slide10-13（4枚）eyebrow「文脈の一覧」nav「入れるもの」page4
- 章5 slide14-16（3枚）eyebrow「とくに効く」nav「入れるもの」page5
- 章6 slide17-20（4枚）eyebrow「落とし穴」nav「入れるもの」page6
- 章7 slide21-23（3枚）eyebrow「いちばん忘れがち」nav「入れるもの」page7
- 章8 slide24-27（4枚）eyebrow「やってみる」nav「やってみる」page8
- 章9 slide28-30（3枚）eyebrow「やってみる」nav「やってみる」page9
- 章10 slide31-33（3枚）eyebrow「今日の1件」nav「やってみる」page10
- 章11 slide34-37（4枚）eyebrow「次回へ」nav「やってみる」page11

各スライドの中身は**pptxの各スライドのテキストをそのまま反映**する（pptx S1=slide01, S2=slide02, … S37=slide37 と1対1。段階的に増える要素をそのまま再現）。カード対比・番号リスト・まとめ帯（kicker）などはpptxのレイアウトに合わせ、2-1で使っている card(hi/pl)/pair/krow/grid6/kicker/sixmini/li 等のクラスで組む。

## 絶対ルール（マキカエシの編集ルール。厳守）
1. **題字（title）は句読点なし・1行**。pptxのtitleに「、」「。」があれば消す。長い題字は `_tfont()` で自動縮小されるのでそのまま渡してよい（改行しない・white-space:nowrap）。
2. **画面に出る「AI」は必ず半角大文字 `AI`**。pptxが「AI」ならOK。小文字や全角があれば直す。
3. 本文は26px以上、本文は上寄せで y<=470 目安（下部にテロップとキャラが載るため）。style.cssの.wrapに収まればよい。
4. **マーカー用の data-mk を仕込む**（後で赤波線を焼くための目印。付けるだけでよい、色は付かない）:
   - 各章の**最後のまとめ帯（kicker）**のテキストを `<span data-mk="k">…</span>` で囲む（kickerヘルパーの mk 引数を使う）。
   - 対比カードが2枚あって片方が「効く/正しい/望ましい」側なら、その**片方のカード本文のみ** data-mk（例 mk="c2"）。両方には付けない。
   - 番号付きリスト（章4の文脈一覧、章8/章10の番号項目など）は各項目に data-mk="g1","g2",… を付ける（順次マーカー用）。
   - 迷ったら「章末kickerに1つ」だけは必ず付ける。

### 迷った点と採用した解釈
1. **章3の題字**: pptx原題「役割は、肩書きではなく何を重要視して判断するかの物差し」は句読点除去後26字で、右上ticksに被る幅になったため「役割は肩書きではなく判断の物差し」に短縮（本文で「何を優先して選ぶか」を補完しているため意味は保持）。他の章の題字はそのまま1行で収まった。
2. **章6の落とし穴フロー**: 4ボックスの連鎖を、矢印の実文字を避けるため矢印なしの横並びカード（左→右で流れを暗示）に。段階リビールで表示数だけflex幅が変わる作り。
3. **章11の要点2つ**: pptxは2枚のカードだが、縦の収まり（下部テロップ回避 y<=470）を優先し `krow`（キー＝役割/文脈）の薄い横行に。「次回」はカード見出しのみ→S35で本文リビール。
4. **章5の対比カード**: 「決まっている／いない」はどちらも肯定的で優劣がないため、カードにはc2を付けず章末kickerのみに `k`。
5. **句読点・記号の正規化**: 本文/kickerは家スタイル（2-1準拠）に合わせ 、。 と全角スペース付きの「AI 」を除去、pptxの「──」「：」は半角スペースに置換。題字のみ全角スペースで2句を分離（章11）。
